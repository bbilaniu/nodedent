## Evidence Handling

This public repository records only non-sensitive identifiers, dates, statuses,
and summaries. Store the following in the clinic's approved compliance
repository:

- the completed and signed PIA;
- transmission receipt and regulator correspondence;
- signatures and staff identities;
- device identifiers, configuration exports, screenshots, and extension lists;
- training attendance and competency records;
- internal dependency reports, findings, and risk acceptances;
- incident, downtime, backup, recovery, retention, and deletion procedures.

Use opaque controlled-record identifiers here. Do not commit patient data,
credentials, passphrases, private network details, or confidential system
configuration.

## Automated Synthetic Evidence

All committed tests use synthetic fixtures. The automated suite passed and
covers, among other logic:

- encrypted vault create, save, load, backup, and restore;
- wrong-passphrase, tampered-backup, and stale-write rejection;
- legacy browser-storage separation, plaintext backup, and explicit deletion;
- export filename minimization and structured case import/export;
- endodontic and operative workflow state, notes, and event behavior;
- application version, privacy text, production CSP, network restrictions, and
  case-storage boundaries.

Automated tests do not establish that a clinic device, operating-system account,
browser profile, downloads path, clipboard policy, screen lock, accessibility
setup, or manual EMR handoff is approved and usable. Complete every applicable
scenario in the target-device checklist before go-live.

## Dependency And Threat Review Boundary

The lockfile contains 259 installed package entries: 4 non-development entries
and 255 development entries, with 75 entries marked optional. The direct
runtime dependencies are React, React DOM, and Zod. The independent reviewer
must verify the exact inventory and classifications from the bound lockfile.

An offline `npm audit --offline --json` invocation on 2026-07-24 reported no
cached vulnerabilities. That result is **not** a current advisory-service query
and is not accepted as the independent dependency review. The independent
reviewer must use a clinic-approved advisory source and environment, document
the report time and database freshness, assess runtime/build reachability, and
sign the separate review packet.

The current threat model remains
[the local clinical threat model](../security/local-clinical-threat-model.md).
The independent review must challenge its assets, trust boundaries, attacker
assumptions, controls, exclusions, and residual risks rather than merely confirm
that a document exists.
